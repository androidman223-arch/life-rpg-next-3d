# マクロ60 — 寝マクロ（〜60分 · 1サイクル）

## おまかせ実行

ユーザーが **「寝マクロ」**（または 60分マクロ / お風呂マクロ）だけ言ったら **追加質問しない**。

1. 本スキルを読む
2. [QUEUE.md](QUEUE.md) の **先頭の未着手** を1件選ぶ
3. サイクル（選ぶ→設計→実装→smoke→終了報告）まで **最後まで** 実行
4. QUEUE と [progress.md](progress.md) を更新

ユーザーが別パックを指定したときだけ、その指定を優先する。

## 指令

**戻ってきたときに「1つ完成していた」と言えるサイズ。**

| 項目 | ルール |
|------|--------|
| **時間** | 目安 **50〜70分** · **75分超えたら打ち切り**して終了報告 |
| **成果** | **1パック**（下のキューから1件 · 複数ファイルOK） |
| **厚さ** | 同じ面で **L1〜L5 を1周** が標準（ファイル追加だけで終わらない） |
| **品質** | Wiki/既存パターンに合わせる · 仮置きは progress に明記 |
| **必須** | `npm run smoke` · 手動確認 **最大5項目** · progress 更新 · 終了報告に **完了した L 層** を書く |

## 呼び方

- **推奨:** **寝マクロ**（おまかせ可）
- **OK:** 60分マクロ / マクロ60 / お風呂マクロ / 夜マクロ

|---|---------------|-------------|

| 手動確認 | 1項目 | 最大5項目 |

## サイクル（固定 · 5ステップ）

### 1. 選ぶ（3分）

[QUEUE.md](QUEUE.md) の先頭未着手、またはユーザー指定。

### 2. 設計メモ（5分）

- 触る `mapSlotId` / ファイルを3行で書く
- `moeSubsystemGuide.js` で担当サブシステムを確認
- 敵なら Wiki 公式名を progress に1行

### 3. 実装（40〜50分）

**パック例 A — AGE 1面磨き**

1. L1 地形の手入れ（`moe3dMacro2AgeTiles.js`）
2. L2 プロップ（`moe3dMacro2L2Props` または Age 専用）
3. L3 spawn pad（敵未実装ならプレースホルダ）
4. ミニマップ色 · アルター spawn 確認

**パック例 B — マクロ１ 敵1種**

1. Wiki 調査 → planned data
2. GLB builder + catalog
3. registry · spawn · smoke 公式チェック

**パック例 C — 拠点室内**

1. BGM マップスロット
2. 入場UI · トースト or 小パネル
3. 生命爆神 or 休憩演出（既存流用可）

### 4. 検証（8分）

```bash
npm run smoke
```

開発中: `__MOE_DEV__.guide()` / `snapshot()` / `invariants()`

### 5. 終了報告（テンプレ）

```
【寝マクロ60】完了
・パック: （例: AGEソレス渓谷 L1〜L3）
・変更: （ファイル bullet 最大8件）
・smoke: pass
・手動: ①… ②… ③…（最大5）
・次のおすすめ: QUEUE #n
```

[progress.md](progress.md) と QUEUE を更新。

## 20機能マクロとの関係

- **20機能マクロ** = 別キュー（[macro-features/QUEUE.md](../macro-features/QUEUE.md)）
- 寝マクロ60で **1セッション = キュー1件** 消化するのが基本

- war_age への敵追加
- MoeFieldMap 7000行分割（macro-0 BACKLOG 扱い）
